# Quality gates

> Status: APPROVED  
> Authority: CANONICAL  
> Last reviewed: 2026-08-16

Гейты применяются пропорционально риску. Маленькое изменение не требует театральной процессии, но основной сценарий всегда должен быть доказан.

## G0. Scope

- пользовательский исход понятен;
- scope и `Not now` зафиксированы;
- критерии наблюдаемы;
- разрешения понятны.

## G1. Product

- изменение связано с проблемой или метрикой;
- нет незаявленного расширения;
- спорные утверждения помечены как гипотезы;
- acceptance criteria актуальны.

## G2. UX

- основной сценарий завершён;
- ошибки и пустые состояния имеют выход;
- контекст не теряется;
- тексты понятны;
- доступность учтена;
- для значимого изменения flow пройден `ux-audit` или эквивалентный независимый review.

## G3. UI

- используется дизайн-система;
- состояния компонентов определены;
- responsive проверен;
- нет переполнения и сломанных длинных данных;
- visual diff просмотрен;
- для значимого UI пройден `visual-qa`.

## G4. Engineering

- патч минимален;
- типы и контракты не ослаблены;
- зависимости обоснованы;
- миграции имеют rollback;
- секретов и лишних данных нет.

## G5. Verification

- релевантные lint/typecheck/tests/build пройдены;
- основной ручной сценарий воспроизведён;
- критический flow покрыт `e2e-review` или эквивалентной воспроизводимой проверкой;
- regression test добавлен для исправленной ошибки;
- известные непроверенные области перечислены.

## G6. Documentation

- `docs-audit` или эквивалентный smoke test подтверждает, что документация соответствует фактам;
- setup-команды, ссылки и contracts актуальны;
- `CURRENT_STATE` и решения синхронизированы;
- новый участник может продолжить без старого чата.

## G7. Handoff / Release

- итоговый diff просмотрен;
- состояние git понятно;
- следующий шаг сформулирован;
- release/deploy не выполнен без разрешения;
- перед важным release выполнен `release-audit` и зафиксирован verdict.

## Приоритет findings

| Приоритет | Значение |
|---|---|
| `P0` | критический риск, потеря данных, серьёзная уязвимость или полный стоп |
| `P1` | основной сценарий сломан или результат неверен |
| `P2` | значимая регрессия, доступность, поддерживаемость или вероятная ошибка |
| `P3` | небольшое улучшение без блокировки |

Review должен содержать путь воспроизведения или конкретное доказательство. Вкусовая рекомендация не должна маскироваться под дефект.

## Минимальные наборы

### Маленький fix

```text
static checks + targeted test + regression check + diff review
```

### UI feature

```text
quality-review + e2e-review + visual-qa + ux-audit + docs-audit
```

### Критическая функция / release

```text
quality-review
+ e2e-review
+ ux-audit / visual-qa where relevant
+ security review
+ performance check where relevant
+ docs-audit
+ release-audit
```

## Release verdict

```markdown
APPROVE
APPROVE WITH KNOWN RISKS
REQUEST CHANGES
BLOCK
```
