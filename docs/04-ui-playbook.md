## Интерфейс как система решений

UI не начинается с градиента. Он начинается с приоритета:

1. Что пользователь должен заметить?
2. Что сравнить?
3. Что сделать?
4. Что можно отложить?
5. Как система покажет результат?

Визуальная иерархия должна отвечать на эти вопросы без экскурсии по экрану.

## Порядок проектирования

1. Контент и приоритеты.
2. Компоновка и сетка.
3. Существующие компоненты и токены.
4. Интерактивные состояния.
5. Адаптивность.
6. Доступность.
7. Визуальная полировка и motion.

## Контракт компонента

Для нового или изменённого компонента опиши:

```markdown
## Purpose
## Anatomy
## Content rules
## Variants
## States
## Behavior
## Responsive rules
## Accessibility
## Tokens
## Examples and anti-patterns
```

## Состояния интерактива

Минимальный набор при релевантности:

| Состояние | Что проверить |
|---|---|
| default | читаемость и доступность действия |
| hover | не является единственным сигналом |
| focus | видим с клавиатуры |
| active/pressed | подтверждает нажатие |
| selected | отличается не только цветом |
| disabled | причина понятна или избегается |
| loading | исключает двойное действие |
| error | объясняет проблему и выход |
| success | подтверждает результат |

## Responsive

Не проектируй только две красивые точки. Опиши поведение между ними:

- минимальная и максимальная ширина контейнера;
- правила колонок;
- переносы и обрезка текста;
- поведение таблиц и сложных форм;
- фиксированные и sticky-элементы;
- safe areas;
- клавиатура на мобильном;
- переполнение по обеим осям.

Контрольные размеры выбирай под продукт. Для веба обычно нужны как минимум узкий mobile, широкий mobile, tablet и desktop.

## Motion

Анимация допустима, если она:

- показывает причинно-следственную связь;
- объясняет смену состояния;
- поддерживает ориентацию;
- не блокирует действие;
- уважает reduced motion.

Не используй motion для маскировки медленного интерфейса.

## Визуальный review

Сравнивай реализацию с источником правды:

- размеры и сетка;
- типографика;
- интервалы;
- цвета и токены;
- состояния;
- длинные тексты;
- системный zoom;
- mobile/desktop;
- реальные данные;
- ошибки и loading.

Скриншот happy path без интерактивной проверки не доказывает качество интерфейса.
