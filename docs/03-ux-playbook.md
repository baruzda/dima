# UX playbook

> Status: APPROVED  
> Authority: CANONICAL  
> Last reviewed: 2026-08-16

## Сначала сценарий

Экран является следствием шага пользователя. Начинай с:

```text
точка входа → намерение → действие → ответ системы → результат → следующий шаг
```

Для каждого шага спроси:

1. Что пользователь пытается сделать?
2. Что он должен знать для решения?
3. Как система подтверждает действие?
4. Что может пойти не так?
5. Как вернуться или продолжить?

## Таблица сценария

| Шаг | Намерение | Действие | Ответ системы | Ошибка/альтернатива | Следующий шаг |
|---|---|---|---|---|---|
| 1 | найти услугу | вводит запрос | показывает релевантные варианты | нет результатов | уточнить запрос |
| 2 | выбрать вариант | открывает карточку | показывает детали | данных недостаточно | вернуться к списку |

## Обязательные состояния

Проверяй релевантность каждого состояния:

- initial;
- loading или skeleton;
- empty;
- partial data;
- success;
- validation error;
- system error;
- offline и retry;
- permission denied;
- disabled;
- cancel, undo и destructive confirmation;
- session expired;
- длинные данные и локализация.

Не все состояния требуют отдельного экрана. Часто достаточно локального ответа компонента.

## Информационная архитектура

- группируй информацию по задаче пользователя, а не по структуре базы данных;
- используй знакомые названия;
- показывай самое нужное в момент решения;
- не заставляй помнить данные между экранами;
- сохраняй контекст при возврате;
- держи основное действие очевидным;
- опасные действия отделяй визуально и подтверждай.

## Тексты интерфейса

Хороший текст:

- называет действие или результат;
- не обвиняет пользователя;
- объясняет ошибку и следующий шаг;
- использует одинаковые термины;
- не подменяет дизайн длинной инструкцией.

Плохо: `Что-то пошло не так`.  
Лучше: `Не удалось сохранить изменения. Проверьте соединение и повторите попытку.`

## Доступность по умолчанию

Проверь:

- логичный порядок фокуса;
- видимый focus state;
- доступные labels;
- управление клавиатурой;
- контраст;
- размер touch targets;
- отсутствие информации только через цвет;
- масштабирование текста;
- понятные ошибки формы;
- поддержку reduced motion, если есть анимация.

## UX-acceptance

Сценарий готов к реализации, когда:

- основной путь завершает пользовательскую задачу;
- альтернативы и ошибки имеют следующий шаг;
- нет тупиков;
- данные не теряются неожиданно;
- пользователь понимает состояние системы;
- QA может вывести тест-кейсы из flow.
