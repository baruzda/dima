# Инженерный playbook

> Status: APPROVED  
> Authority: CANONICAL  
> Last reviewed: 2026-08-16

## До изменения кода

Сначала найди:

- точку входа;
- фактический execution path;
- владельца состояния;
- контракты данных и API;
- существующие паттерны;
- тесты;
- команды разработки;
- связанные документы;
- неизвестные локальные изменения.

Не начинай с создания нового файла, пока не проверил, нет ли уже подходящего места.

## Принцип минимального обратимого патча

Хороший патч:

- решает один определённый исход;
- затрагивает минимум областей;
- следует существующим соглашениям;
- имеет понятную проверку;
- легко откатывается;
- не содержит попутной уборки.

Рефакторинг допустим, когда он необходим для задачи, а не просто заметен по дороге.

## Зависимости

Перед новой production-зависимостью зафиксируй:

```markdown
Проблема:
Почему текущих средств недостаточно:
Выбранная зависимость:
Размер и runtime-cost:
Security/maintenance риск:
Альтернативы:
План удаления:
```

## Контракты и данные

Отдельное решение требуется для:

- изменения публичного API;
- схемы базы данных;
- формата событий;
- авторизации;
- хранения персональных данных;
- кэширования с изменением консистентности;
- миграций без простого rollback.

Сначала обеспечь совместимость, затем переключение, затем удаление старого пути.

## Тестовая пирамида задачи

Выбирай самый дешёвый слой, который доказывает поведение:

- unit для чистой логики;
- component для состояний UI;
- integration для границ модулей и API;
- e2e для критичного пользовательского сценария;
- ручная проверка для визуального и системного поведения.

Тест должен падать до исправления или явно доказывать новое требование.

## Git-гигиена

- одна логическая задача на ветку;
- один успешный вертикальный срез на коммит;
- scoped staging вместо `git add .`;
- не переписывать чужую историю;
- не включать неизвестные изменения;
- не коммитить секреты и generated noise;
- commit message описывает результат, а не процесс.

Пример:

```text
feat(onboarding): preserve draft after validation error
```

## Безопасность

Проверяй:

- доверительные границы и права;
- валидацию на сервере;
- хранение и логирование секретов;
- обработку пользовательского ввода;
- доступ к данным другого пользователя;
- небезопасные URL и redirects;
- зависимости и supply-chain;
- destructive operations;
- персональные данные в аналитике.
