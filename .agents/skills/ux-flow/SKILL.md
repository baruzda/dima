# UX Flow

## Вход

- утверждённая проблема и пользователь;
- основной JTBD;
- границы MVP;
- ограничения платформы и данных.

## Процесс

1. Сформулируй пользовательскую цель и точку входа.
2. Построй основной путь от намерения до результата.
3. Удали шаги, которые не меняют решение пользователя или состояние системы.
4. Опиши альтернативные ветки и возвраты.
5. Для каждого шага зафиксируй:
   - намерение пользователя;
   - действие;
   - ответ системы;
   - необходимую информацию;
   - следующий понятный шаг.
6. Добавь релевантные состояния:
   - initial;
   - loading;
   - empty;
   - success;
   - validation error;
   - system error;
   - permission denied;
   - offline/retry;
   - cancel/undo.
7. Спроектируй информационную архитектуру и навигацию.
8. Проверь тексты, доступность, сохранение контекста и критичные ошибки.
9. Сформулируй сценарии для прототипа и тестирования.

## Результат

- диаграмма или нумерованный flow;
- список экранов/поверхностей;
- таблица состояний;
- контентные требования;
- UX-критерии приёмки;
- риски и открытые вопросы.

## Готово, когда

Инженер и UI-дизайнер понимают полный сценарий, а QA может вывести из него тестовые случаи.
