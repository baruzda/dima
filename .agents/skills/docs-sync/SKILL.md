# Documentation Sync

## Процесс

1. Сопоставь фактический код, принятые решения и текущие документы.
2. Найди:
   - устаревшие утверждения;
   - дубли;
   - оборванные ссылки;
   - решения без причины;
   - задачи без статуса;
   - скрытые допущения.
3. Обнови:
   - `PROJECT_BRIEF.md`, только если изменился продуктовый контракт;
   - `CURRENT_STATE.md`, всегда по факту;
   - `DECISION_LOG.md`, для значимых решений;
   - `TASKS.md`, для следующей работы;
   - спецификации и README, если изменились интерфейсы или запуск.
4. Для заменённых документов используй `Status: SUPERSEDED` и ссылку на замену.
5. Не удаляй историю решений.
6. Создай краткий handoff:
   - сделано;
   - проверено;
   - не сделано;
   - риски;
   - следующий шаг;
   - состояние git.
7. Проверь ссылки из `docs/INDEX.md`.

## Готово, когда

Новый участник может продолжить работу без чтения старого чата и без угадывания фактического состояния.
