# Bug Triage

## Процесс

1. Зафиксируй:
   - фактическое поведение;
   - ожидаемое поведение;
   - среду;
   - шаги;
   - частоту;
   - влияние.
2. Воспроизведи проблему или собери максимально близкое доказательство.
3. Найди точку первого расхождения между ожидаемым и фактическим потоком.
4. Проследи код, данные, состояние, сеть и логи.
5. Отдели:
   - подтверждённую первопричину;
   - сопутствующие симптомы;
   - неподтверждённые гипотезы.
6. Определи минимальное исправление.
7. Добавь regression test или чёткий сценарий ручной проверки.
8. Проверь соседние пути, которые мог затронуть fix.
9. Не маскируй ошибку отключением типов, тестов или обработки исключений.
10. Обнови документацию, если фактический контракт изменился.

## Формат finding

```markdown
### Симптом
### Воспроизведение
### Первопричина
### Доказательство
### Минимальное исправление
### Regression test
### Остаточный риск
```

## Готово, когда

Причина доказана, исправление ограничено, а повторное появление ошибки обнаруживается тестом или воспроизводимым сценарием.
