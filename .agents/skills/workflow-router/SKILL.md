# Workflow Router

## Цель

Выбрать **минимальный достаточный процесс** для задачи, а не запускать весь набор skills и agents автоматически.

## Вход

- запрос пользователя;
- текущее состояние проекта;
- затронутые области;
- риск и обратимость;
- наличие UI, данных, auth, интеграций и production impact.

## Процесс

1. Прочитай `docs/13-process-recipes.md` и `docs/12-verification-strategy.md`.
2. Классифицируй задачу:
   - новый продукт;
   - новая функция;
   - UI-фича;
   - redesign;
   - bug/UI bug;
   - audit;
   - refactor;
   - integration/automation;
   - AI feature;
   - PR/release;
   - docs-only;
   - continuation/handoff.
3. Оцени риск:
   - low;
   - medium;
   - high;
   - critical.
4. Выбери ближайший рецепт.
5. Удали лишние шаги, которые не добавляют доказательства или снижения риска.
6. Добавь обязательные проверки из verification matrix.
7. Определи, какие шаги могут идти параллельно read-only.
8. Не запускай нескольких write-agents в одну ветку/worktree.
9. Укажи точки, где требуется отдельное разрешение пользователя.
10. Верни один рекомендуемый маршрут.

## Формат результата

```markdown
## Task class
## Risk
## Recommended recipe
1. ...
2. ...

## Parallel read-only work
## Required evidence
## Approval gates
## Skipped steps and why
```

## Правило

Не включай skill или agent только потому, что он существует. Каждый шаг должен отвечать на вопрос:

```text
Какую неопределённость, ошибку или риск этот шаг уменьшает?
```

Если разумного ответа нет, шаг лишний.

## Готово, когда

Следующий агент понимает точный маршрут работы, обязательные проверки и границы автономности без необходимости заново выбирать процесс.
