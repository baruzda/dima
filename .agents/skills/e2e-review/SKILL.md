# E2E Review

## Цель

Доказать, что пользователь может пройти критический сценарий от точки входа до наблюдаемого результата.

## Процесс

1. Прочитай acceptance criteria, UX-flow и текущий implementation scope.
2. Определи 1–5 критических сценариев, а не полный каталог кнопок.
3. Для каждого сценария зафиксируй:
   - preconditions;
   - test data;
   - entry point;
   - user actions;
   - system responses;
   - final observable result.
4. Используй существующий E2E stack проекта. Для web предпочитай Playwright, если проект уже его использует или его добавление согласовано.
5. Проверяй минимум:
   - основной путь;
   - одну наиболее вероятную ошибку/отказ;
   - повторное действие или retry, если релевантно.
6. Используй стабильные локаторы и контролируемые данные. Не привязывай тест к случайной DOM-структуре.
7. Сохрани evidence: команда, результат, screenshot/video/trace при наличии.
8. Если найден дефект, верни reproducible finding и regression scenario.
9. Не меняй продуктовый scope во время review.

## Результат

```markdown
## Scenarios
## Environment
## Automated evidence
## Manual evidence
## Findings P0-P3
## Regressions to automate
## Verdict
## Not verified
```

## Готово, когда

Критический пользовательский результат подтверждён воспроизводимым сценарием, а непроверенные области перечислены явно.
