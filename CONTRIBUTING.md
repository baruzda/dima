# Contributing

## Принцип

Изменение должно улучшать повторяемый рабочий процесс, а не просто добавлять ещё один длинный промт.

## Перед изменением

1. Опиши проблему, которую решает изменение.
2. Укажи, какой файл является источником правды.
3. Проверь, не дублируется ли правило в другом месте.
4. Выбери минимальный scope.

## Требования к навыкам

Каждый `SKILL.md` обязан иметь:

- YAML-frontmatter с `name` и `description`;
- ясные условия срабатывания;
- границы и случаи, когда навык не нужен;
- входные данные;
- последовательность действий;
- формат результата;
- критерий завершения.

## Требования к агентам

Каждый `.codex/agents/*.toml` обязан иметь:

- `name`;
- `description`;
- `developer_instructions`;
- узкую роль;
- понятный режим доступа;
- запрет на выход в соседние роли без запроса оркестратора.

## Документация

- Обновляй связанные документы вместе с изменением.
- Не создавай новый канонический файл, если можно расширить существующий.
- Помечай заменённые решения как `SUPERSEDED`.
- Добавляй значимые решения в журнал.

## Проверка

```bash
bash scripts/validate.sh
```

## Pull request

PR должен объяснять:

- проблему;
- выбранное решение;
- изменённые контракты;
- способ проверки;
- влияние на навыки, агентов и документацию.
