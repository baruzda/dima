# Dima: операционная система для вайбкодинга

Набор правил, ролей, навыков, агентов и шаблонов для работы с Codex и ChatGPT без режима «написали что-то красивое и надеемся, что оно работает».

Репозиторий помогает пройти полный цикл:

> идея → продуктовая рамка → UX-сценарий → UI-спецификация → реализация → проверка → документация

## Что внутри

| Раздел | Зачем нужен |
|---|---|
| `AGENTS.md` | Основные правила, которые Codex читает перед работой |
| `.agents/skills/` | Повторяемые рабочие процессы в формате `SKILL.md` |
| `.codex/agents/` | Узкие проектные субагенты: продукт, UX, UI, код, QA, документация, безопасность |
| `docs/` | Канонические правила команды |
| `templates/` | Шаблоны брифа, PRD, сценариев, дизайн-спеки, задач, решений и передачи контекста |
| `scripts/` | Установка, перенос в новый проект и проверка структуры |
| `CHATGPT_PROJECT_INSTRUCTIONS.md` | Готовые инструкции для проекта в ChatGPT |

## Главная идея

Вайбкодинг полезен, когда модель получает не поток пожеланий, а управляемый контур:

1. **Понять задачу.**
2. **Зафиксировать решение.**
3. **Сделать минимальный проверяемый шаг.**
4. **Проверить результат независимо.**
5. **Обновить источник правды.**

Этот репозиторий не заставляет новичка изображать корпорацию из одного человека. Роли включаются только там, где они уменьшают риск ошибки.

## Рабочий стек

В [`docs/11-tool-stack.md`](docs/11-tool-stack.md) зафиксирована карта приложений и сервисов по этапам работы.

Базовый маршрут сейчас выглядит так:

```text
ChatGPT         → продукт, исследование, постановка задачи
Figma           → UX/UI, компоненты, прототип
Codex           → код, тесты, review, документация
GitHub          → source of truth и история изменений
Browser         → проверка реального пользовательского сценария
```

Дополнительные инструменты подключаются по необходимости:

```text
Cursor          → альтернативный IDE-first coding workflow
Product Design  → UX-аудит и быстрые прототипы
n8n             → интеграции и автоматизация
Adobe/Photoshop → растровая графика
Remotion        → программная генерация видео
Yandex Wordstat → проверка поискового спроса
```

Принцип простой: **одна повторяющаяся задача → один предпочтительный инструмент**. Новый сервис не добавляется в основной стек только потому, что выглядит интересно.

## Для первого знакомства

Открой [`START_HERE.md`](START_HERE.md). Там один учебный маршрут без лишней теории.

## Быстрый старт

### Вариант A: использовать правила в одном проекте

```bash
git clone https://github.com/baruzda/dima.git
cd dima
bash scripts/bootstrap-project.sh /путь/к/твоему-проекту
```

Скрипт не перезаписывает существующие файлы без флага `--force`.

```bash
bash scripts/bootstrap-project.sh /путь/к/твоему-проекту --force
```

### Вариант B: установить навыки и агентов глобально

```bash
git clone https://github.com/baruzda/dima.git
cd dima
bash scripts/install-global.sh
```

После установки навыки будут доступны из разных репозиториев. Не ставь один и тот же набор одновременно глобально и локально в конкретный проект: Codex может показать дубликаты навыков.

### Проверить комплект

```bash
bash scripts/validate.sh
```

## Настройка ChatGPT

1. Создай отдельный проект в ChatGPT.
2. Добавь в источники `CHATGPT_PROJECT_INSTRUCTIONS.md`, нужные документы из `docs/` и документацию своего продукта.
3. Скопируй содержимое `CHATGPT_PROJECT_INSTRUCTIONS.md` в инструкции проекта.
4. Для новой задачи прикладывай актуальные `PROJECT_BRIEF.md`, `CURRENT_STATE.md` и `DECISION_LOG.md`.

## Первая команда для нового проекта

```text
Используй навык `$project-kickoff`.

Изучи репозиторий и создай продуктовую основу проекта.
Не начинай реализацию, пока не зафиксированы:
1) пользователь и проблема;
2) главный сценарий;
3) границы MVP;
4) критерии готовности;
5) ближайший минимальный вертикальный срез.

Недостающие данные оформи как явные допущения. В конце предложи один рекомендуемый следующий шаг.
```

## Ежедневный цикл

```text
1. Открой CURRENT_STATE.md.
2. Выбери одну задачу с проверяемым результатом.
3. Вызови нужный навык или агента.
4. Реализуй минимальный срез.
5. Запусти проверки.
6. Проведи независимый review.
7. Обнови документацию и handoff.
```

## Каталог навыков

| Навык | Когда применять |
|---|---|
| `project-kickoff` | Новая идея, пустой или плохо описанный репозиторий |
| `product-discovery` | Нужно определить проблему, аудиторию, ценность и MVP |
| `ux-flow` | Нужно спроектировать путь пользователя и состояния интерфейса |
| `ui-spec` | Нужно превратить сценарий или макет в реализационную UI-спецификацию |
| `implementation-plan` | Нужно изучить код и составить план без изменений |
| `build-feature` | Границы задачи согласованы, можно реализовывать |
| `bug-triage` | Есть ошибка, но причина ещё не доказана |
| `quality-review` | Нужна независимая проверка результата |
| `docs-sync` | Нужно синхронизировать источник правды и передать контекст |

## Каталог агентов

| Агент | Режим |
|---|---|
| `product_strategist` | Read-only: проблема, ценность, scope, критерии |
| `ux_architect` | Read-only: сценарии, состояния, IA, доступность |
| `ui_reviewer` | Read-only: визуальная и компонентная проверка |
| `code_mapper` | Read-only: карта кода и рисков |
| `implementation_worker` | Write: небольшая реализация по утверждённому плану |
| `qa_reviewer` | Read-only: ошибки, регрессии, тесты |
| `docs_keeper` | Write: документация и handoff |
| `security_reviewer` | Read-only: секреты, доверительные границы, опасные изменения |

## Основные ограничения

- Не путать обсуждение с разрешением менять файлы.
- Не делать параллельные записи нескольких агентов в одну ветку или worktree.
- Не добавлять зависимости «для удобства» без доказанной необходимости.
- Не пушить, не мержить, не деплоить и не менять внешние системы без явного разрешения.
- Не считать задачу завершённой без проверок и наблюдаемого результата.
- Не оставлять документацию в прошлом коммите, если поведение уже изменилось.
- Не хранить секреты, токены, пароли и персональные данные в репозитории.

## Как читать документацию

Начни с [`docs/INDEX.md`](docs/INDEX.md). Канонические документы ограничены небольшим набором, чтобы правила не превращались в бумажный лабиринт.
